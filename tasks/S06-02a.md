# S06-02a — view model of the Workshop screen

File to edit: src/view/workshop-view.ts

Goal: The pure data behind the Workshop screen: three columns of symbols the player has unlocked, the power used out of the budget, a preview of the creature once three symbols are picked, and whether the player can afford to make it. The screen only draws this. Nothing here touches the DOM, a clock or `Math.random`.

Signatures (do not change; the file already exports the types and these stubs):
```ts
export type SymbolKind = 'element' | 'form' | 'trait';
export interface Selection { readonly element: string | null; readonly form: string | null; readonly trait: string | null }
export const EMPTY_SELECTION: Selection
export function toggleSymbol(selection: Selection, kind: SymbolKind, id: string): Selection
export function buildWorkshopView(data: CombatData, unlocked: Unlocked, ink: number, selection: Selection): WorkshopView
```
Use the existing `previewCreature` and `craftCreature` from `src/core/workshop/workshop.ts` (read it first); do not repeat their rules.

`toggleSymbol`:
- Returns a new object; the input is not changed. When `selection[kind] === id` that slot becomes `null`; otherwise it becomes `id`. The other two slots stay as they were. The id is not checked against any data.

`buildWorkshopView(data, unlocked, ink, selection)`:
- `columns`: always three, in the order element, form, trait (`kind` set accordingly). A column lists only the symbols of `data.symbols` whose id is in the matching array of `unlocked` (`elements`, `forms`, `traits`), in the order of `data.symbols`. Each choice is `{ id, cost, selected }`, where `cost` is the symbol's `cost` and `selected` is true when `selection[kind] === id`. Ids in `unlocked` that do not exist in `data.symbols` are ignored.
- `power.max` is `data.balance.powerBudget`. `power.used` is the sum of the costs of the picked symbols that exist in `data.symbols` (an id that does not exist counts 0; a picked symbol that is not unlocked still counts).
- `ink` is the `ink` argument, unchanged.
- When any of the three slots is `null`: `preview` is `null`, `canCraft` is false, `blocked` is `'incomplete'`.
- Otherwise ask `previewCreature(data, unlocked, spec)` with the three picked ids. When it fails, `preview` is `null`, `canCraft` false and `blocked` is its error (`'workshop.error.unknown_symbol'`, `'workshop.error.locked_symbol'` or `'workshop.error.over_budget'`).
- When it succeeds, `preview` is `{ cardId, attack, health, powerCost, inkCost, emberCost }` taken from the preview (`attack` and `health` from `stats`, `powerCost` is `stats.cost`). Then ask `craftCreature(data, unlocked, ink, spec)`: when it works, `canCraft` is true and `blocked` is `null`; when it fails (not enough ink), `canCraft` is false and `blocked` is its error, but `preview` stays so the player sees the price.
- Throws an `Error` when `data.balance.powerBudget` is undefined or `data.balance.workshop` is missing.
- Never changes its arguments. No Math.random, no Date.now, no `new Date()`, no new dependencies, no Node APIs, `import type` for types.

Examples (data: the test fixture with `powerBudget: 10`, `leftoverHealth: 1`, `workshop: { emberCost: 2, inkPerPower: 4 }`; unlocked elements ogien, woda, ziemia, wiatr, forms wilk, kruk, sowa, jelen, traits gniew, smutek, spryt, odwaga):
- Picking only `woda`: `power` is `{ used: 2, max: 10 }`, `preview` null, `blocked` `'incomplete'`.
- Picking `woda`, `kruk`, `smutek` with 30 ink: `preview` is `{ cardId: 'woda-kruk-smutek', attack: 2, health: 8, powerCost: 6, inkCost: 24, emberCost: 2 }`, `canCraft` true, `blocked` null. With 23 ink: `canCraft` false, `blocked` `'workshop.error.not_enough_ink'`, same preview. With exactly 24 ink: `canCraft` true.
- Picking `grom` (not unlocked), `kruk`, `smutek` with 99 ink: `power.used` is 7, `preview` null, `canCraft` false, `blocked` `'workshop.error.locked_symbol'`.

Lint: ESLint has the rule `no-useless-assignment` on. Do not give a variable a first value that every later branch overwrites, for example `let blocked: CraftBlock | null = null;` followed by `blocked = 'incomplete'` in one branch and `blocked = craftResult.error` or `blocked = null` in the others: that is an error. Instead return early from each case, for example `if (slot is null) return { columns, power, ink, preview: null, canCraft: false, blocked: 'incomplete' };`, then `if (!previewResult.ok) return { ..., blocked: previewResult.error };`, and so on.
