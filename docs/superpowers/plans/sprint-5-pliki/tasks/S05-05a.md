# S05-05a — local telemetry log

File to edit: src/core/telemetry/log.ts

Goal: A pure, immutable log of finished combats for the tester build. The game layer adds one record per combat, the platform layer saves `serializeLog(log)` in local storage and gives it to the tester as a file or text. Nothing here reads a clock, a storage or the network.

Signatures (do not change; the file already exports them as stubs):
```ts
export const TELEMETRY_SCHEMA = 1;
export const MAX_RECORDS = 200;
export interface CombatRecord { seed; enemyId; outcome: 'won' | 'lost'; turns; hpLeft; hpMax; ritualUsed; durationMs }
export interface LogMeta { logId: number; build: string; startedAt: string }
export interface TelemetryLog extends LogMeta { schema: 1; records: readonly CombatRecord[] }
export function createLog(meta: LogMeta): TelemetryLog
export function appendRecord(log: TelemetryLog, record: CombatRecord): TelemetryLog
export function serializeLog(log: TelemetryLog): string
export function parseLog(text: string): TelemetryLog | null
```

Rules:
- Valid meta: `logId` is an integer from 0 to 4294967295; `build` and `startedAt` are strings with at least one non-space character. Anything else → `RangeError`. `createLog` returns `{ schema: 1, logId, build, startedAt, records: [] }`.
- Valid record: `seed` is an integer from 0 to 4294967295; `enemyId` is a string with at least one character; `outcome` is `'won'` or `'lost'`; `turns` is an integer ≥ 1; `hpMax` is an integer ≥ 1; `hpLeft` is an integer from 0 to `hpMax`; `ritualUsed` is a boolean; `durationMs` is a finite number ≥ 0. Anything else → `RangeError` (also a missing field or a field of the wrong type).
- `durationMs` is stored rounded to a whole number with `Math.round`, so 1234.5 becomes 1235 and 0.4 becomes 0.
- `appendRecord` returns a new log with the (normalised) record added at the end and never changes its input. When the result would have more than `MAX_RECORDS` records, the oldest ones are dropped, so the newest `MAX_RECORDS` stay in order.
- Extra properties of a record are ignored (not stored).
- `serializeLog` returns `JSON.stringify(value, null, 2) + '\n'` where `value` has the keys in this order: `schema`, `logId`, `build`, `startedAt`, `records`; each record has its keys in the order of `CombatRecord` above (`seed`, `enemyId`, `outcome`, `turns`, `hpLeft`, `hpMax`, `ritualUsed`, `durationMs`). An empty `records` array is written as `[]`.
- `parseLog(text)` accepts exactly what `serializeLog` writes (and any JSON with the same structure, any whitespace). It returns a log equal to the one serialised. It returns `null` (never throws) when: the text is not JSON; the top level is not an object; `schema` is not `1`; meta is invalid; `records` is not an array; any record is invalid (same rules as above). A log with more than `MAX_RECORDS` records is not an error: only the newest `MAX_RECORDS` are kept.
- `parseLog(serializeLog(log))` equals `log` for every valid log.
- No Math.random, no Date.now, no `new Date()`, no new dependencies, no Node APIs, `import type` for types.

Edge cases:
- `createLog({ logId: -1, build: 'a', startedAt: 'x' })` → RangeError. `logId: 1.5` → RangeError. `build: '   '` → RangeError.
- `durationMs: NaN`, `Infinity`, `-1` → RangeError. `durationMs: -0.4` → RangeError (negative before rounding).
- `hpLeft: 3, hpMax: 2` → RangeError. `turns: 0` → RangeError. `outcome: 'draw'` → RangeError.
- `parseLog('')`, `parseLog('null')`, `parseLog('[]')`, `parseLog('{')` → null.
