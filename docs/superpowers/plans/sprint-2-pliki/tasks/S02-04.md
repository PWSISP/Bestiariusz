# S02-04 — Ember (Żar): turn budget and card costs

File to edit: src/core/combat/ember.ts

Goal: the energy a player spends to play cards. A turn gives `EMBER_PER_TURN` (= 3) ember; unused ember does not carry over (the reducer resets it, this module only does the arithmetic).

Signatures (do not change): `EMBER_PER_TURN`, `canAfford`, `spendEmber`, `gainEmber`, `playableIndexes` in the stub. Parameter names in the stub start with an underscore only because the stub does not use them; use normal names.

Rules:
- Every number argument (`ember`, `cost`, `amount`) must be an integer >= 0, otherwise throw `RangeError` (NaN, Infinity, negatives and fractions included). The check runs before anything else, also in `canAfford`.
- `canAfford(ember, cost)`: `cost <= ember`.
- `spendEmber(ember, cost)`: returns `ember - cost`; throws `RangeError` when the cost is higher than the ember.
- `gainEmber(ember, amount)`: returns `ember + amount`; there is no cap.
- `playableIndexes(hand, costOf, ember)`: indexes (ascending) of the cards in `hand` whose `costOf(cardId)` is not `null` and affordable. `null` means the card cannot be played at all (a curse). The same card id twice in the hand is listed twice. `ember` is validated like above; the costs are validated by `canAfford`.

Rules: no Math.random, no Date.now, no new dependencies, no Node APIs.
Tests: tests/S02-04.test.ts (do not edit).
