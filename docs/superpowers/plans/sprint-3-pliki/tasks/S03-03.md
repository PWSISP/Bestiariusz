# S03-03 — Seven-character creature code

File to edit: src/core/creature-code.ts

Goal: a creature can be shared as a short code that a person can read out loud or type: three symbols, a visual variant and a checksum, in exactly 7 characters. The code must survive typing mistakes: a wrong character or two swapped neighbours must be detected, never decoded into a different creature.

Signatures (do not change): `CODE_ALPHABET`, the `CreatureCode` interface, `encodeCreatureCode(symbols, creature)` and `decodeCreatureCode(symbols, code)` in the stub. Parameter names in the stub start with an underscore only because the stub does not use them; use normal names.

Encoding (every step is described in the comments of the stub; follow them literally):

```text
e, f, t = index of the element, form, trait in symbols.elements / .forms / .traits
P = e * 2^16 + f * 2^12 + t * 2^8 + variant          (version 0 adds nothing; P < 2^21)
C = ((P XOR floor(P / 128)) * 31 + 677) mod 16384
V = P * 16384 + C                                    (up to 2^35: no bitwise operators on V)
code = V as 7 base-32 digits of CODE_ALPHABET, most significant first, padded with "0"
```

`encodeCreatureCode` throws `RangeError` when an id is unknown, when `e >= 8`, `f >= 16` or `t >= 16`, or when `variant` is not an integer in `0..255`.

`decodeCreatureCode` returns `null` (never throws) for anything it cannot read:
1. Normalise: uppercase; remove every "-" and every whitespace character; "O" becomes "0"; "I" and "L" become "1".
2. The result must be exactly 7 characters, all in `CODE_ALPHABET`.
3. `V` from the digits; `P = floor(V / 16384)`, `C = V mod 16384`.
4. `null` when `C` is not the checksum of `P`, when the version `floor(P / 2^19)` is not 0, or when `e = floor(P / 2^16) mod 8`, `f = floor(P / 2^12) mod 16` or `t = floor(P / 2^8) mod 16` is not an index of the corresponding array.
5. Otherwise `{ element, form, trait, variant: P mod 256 }` with the ids found at those indexes.

Known vectors (symbols in the order of `src/data/symbols.json`; the tests check these):
- ogien · wilk · gniew · variant 0 → `00000N5`
- grom · wilk · gniew · variant 0 → `4000EN5`
- woda · sowa · smutek · variant 137 → `1464P0V`
- wiatr · jelen · glod · variant 255 → `3AKZYRF`

Rules: no Math.random, no Date.now, no new dependencies, no Node APIs, `import type` for types. Do not use BigInt or `>>>`/`<<` on `V`: JavaScript bitwise operators cut numbers to 32 bits.

Edge cases:
- lowercase and hyphenated input like `4000-en5` decodes like `4000EN5`
- a code with a letter outside the alphabet (for example "U") or of the wrong length → `null`
- a valid code with one character replaced by any other character of the alphabet, or with two neighbouring different characters swapped, must decode to `null` (the tests try all of them for three codes); the checksum above guarantees it
