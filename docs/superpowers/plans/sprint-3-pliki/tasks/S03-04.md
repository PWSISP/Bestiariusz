# S03-04 — Legend of a creature, as translation keys

File to edit: src/core/legend.ts

Goal: every creature card shows one sentence of legend, built from its three symbols, in Polish and English, with the right grammatical gender (Polish: "zrodzony" / "zrodzona"). The core never builds texts: it returns translation keys and the UI (`src/i18n/legend.ts`, written separately) translates and joins them. A few special combinations have a hand-written legend instead.

Signatures (do not change): the `Legend` interface, `legendKey(spec)` and `describeLegend(symbols, spec, special)` in the stub. Parameter names in the stub start with an underscore only because the stub does not use them; use normal names.

`legendKey(spec)` returns `"<element>:<form>:<trait>"`, for example `"grom:wilk:gniew"`. It does not check that the symbols exist.

`describeLegend(symbols, spec, special)`:
1. Find the element, form and trait in `symbols`. If any is missing throw an `Error`, even when the combination is listed in `special`.
2. When `special` contains `legendKey(spec)`: return `{ key: "legend.special.<element>_<form>_<trait>", parts: null }`, for example `"legend.special.grom_wilk_gniew"`.
3. Otherwise `key` is `"legend.born.f"` when `form.gender` is `"f"` and `"legend.born.m"` when it is `"m"`, and `parts` is:
   - `adjective`: `"symbol.trait.<trait>.adjective_<g>"` where `<g>` is the gender of the form (`m` or `f`),
   - `form`: `"symbol.form.<form>.name"`,
   - `element`: `"symbol.element.<element>.of"`.

Never modify the arguments.

Rules: no Math.random, no Date.now, no new dependencies, no Node APIs, `import type` for types.

Edge cases:
- a combination that differs from a special one in one symbol is not special
- a special entry for a combination that does not exist in the symbols is never looked at; only the creature being described matters
- all 150 combinations of the MVP symbols get a legend

Tests: tests/S03-04.test.ts (do not edit).

Done when: vitest, tsc and eslint pass with no errors.
