# S03-02 — Rating a creature and listing the valid ones

File to edit: src/core/creatures.ts

Goal: the Workshop (S03-07) and the balance test (S03-08) need to know, for any three symbols, what the creature costs, whether it fits the power budget and what its attack and health are. Pure functions over the symbol data.

Signatures (do not change): the `CreatureStats` interface, `evaluateCreature(symbols, spec, rules)` and `listValidCreatures(symbols, powerBudget)` in the stub. Parameter names in the stub start with an underscore only because the stub does not use them; use normal names. `StatRules` is `{ powerBudget: number; leftoverHealth: number }` and comes from `src/core/combat/creature.ts` (import type).

`evaluateCreature(symbols, spec, rules)`:
- Find the element, form and trait of `spec` in `symbols.elements`, `symbols.forms` and `symbols.traits` by `id`. If any of them is missing, throw an `Error` (not a `RangeError`).
- `cost` = `element.cost + form.cost + trait.cost`.
- `valid` = `cost <= rules.powerBudget`. `overBudgetBy` = `max(0, cost - rules.powerBudget)`.
- `attack` = `max(0, form.baseAttack + element.attackBonus + trait.attackMod)`.
- `health` = `max(1, form.baseHealth + element.healthBonus + trait.healthMod + bonus)`, where `bonus` = `(rules.powerBudget - cost) * rules.leftoverHealth` for a valid creature and `0` for an invalid one.
- An invalid creature still gets `attack` and `health` (without the bonus).

`listValidCreatures(symbols, powerBudget)` returns a `CreatureSpec` (`{ element, form, trait }` with ids) for every combination of one element, one form and one trait whose cost is `<= powerBudget`. Order: by element, then form, then trait, each in the order of the arrays in `symbols`. An empty array when nothing fits.

Never modify `symbols`, `spec` or `rules`.

Rules: no Math.random, no Date.now, no new dependencies, no Node APIs, `import type` for types.

Edge cases:
- a creature that costs exactly `powerBudget` is valid and gets no bonus (`bonus` = 0)
- `leftoverHealth` of `0` gives no bonus at all
- an attack that would be negative becomes `0`; a health below `1` becomes `1`

Tests: tests/S03-02.test.ts (do not edit).

Done when: vitest, tsc and eslint pass with no errors.
